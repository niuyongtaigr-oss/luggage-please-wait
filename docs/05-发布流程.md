# 发布流程 · 可重复执行

> 当前仓库 `niuyongtaigr-oss/luggage-please-wait` 是**流程验证**用的。
> 正式建库时照这份文档重做一遍即可，全程约 5 分钟。

---

## 前置

```bash
gh auth status          # 必须已登录，且 token 含 repo 权限
git --version           # 任意 2.x
```

本项目**零依赖**，不需要 node_modules、不需要构建。

---

## 一、本地建库并整理提交

```bash
cd luggage_brief
git init -b main

# 忽略规则要先有，避免把临时目录推上去
cat > .gitignore <<'EOF'
node_modules/
.DS_Store
_t/
_tmp/
*.log
.env
.env.*
EOF

git add .gitignore README.md tools shots
git commit -m "chore: 初始化仓库、自测脚本与截图"

git add index.html data.js
git commit -m "feat: 四页原型与视觉系统"

git add api.js config.js supabase
git commit -m "feat(live): Supabase 双轨接入与自动降级"

git add docs kiro-spec
git commit -m "docs: Kiro Spec 三件套与交付文档"
```

> **为什么要分四次提交**：按关注点拆，不是按时间拆。
> 一个 `initial commit` 塞 28 个文件，评委翻仓库时看不出你在想什么。

**推前自测：**

```bash
bash tools/selftest.sh     # 必须输出「✓ 全部通过（9 组断言）」
```

## 二、建远程仓库并推送

```bash
gh repo create luggage-please-wait \
  --public \
  --source=. \
  --remote=origin \
  --push \
  --description "行李箱请等等 · 把「我要走」这个念头，交给陌生人审一遍。四页单文件 Web Demo，零依赖，断网可跑。"
```

**必须是 public** —— 免费版 Pages 不支持私有仓库。

如果先建错了名字，改名是一条命令，Pages 地址会自动跟着变，旧地址 301 跳转：

```bash
gh repo rename 新名字 --yes
git remote set-url origin git@github.com:<owner>/新名字.git
```

---

## 三、开启 Pages

```bash
gh api -X POST repos/<owner>/<repo>/pages \
  --input - <<'JSON'
{"source":{"branch":"main","path":"/"}}
JSON
```

取回地址：

```bash
gh api repos/<owner>/<repo>/pages --jq '.html_url'
```

**首次构建大约 60 秒**，期间访问是 404，属正常：

```bash
# 轮询到 200 为止
until [ "$(curl -s -o /dev/null -w '%{http_code}' https://<owner>.github.io/<repo>/)" = "200" ]; do
  sleep 5; echo -n "."
done
```

## 四、打 tag（回滚点）

```bash
git tag -a demo-ok-1 -m "可完整演示版本"
git push origin demo-ok-1
```

**每次确认能走完四页就打一个**：`demo-ok-1`、`demo-ok-2`……

现场改坏了，一条命令回到上一个能用的状态：

```bash
git reset --hard demo-ok-1 && git push --force
```

## 五、邀请伙伴（可选）

```bash
gh api -X PUT repos/<owner>/<repo>/collaborators/<对方的 GitHub 用户名> \
  -f permission=push
```

对方会收到邮件邀请，**必须点接受**才生效。明早入场第一件事就是确认这个。

## 六、发布后验证清单

逐条打勾，全过才算发布成功：

- [ ] `https://<owner>.github.io/<repo>/` 返回 200
- [ ] 页面标题是「行李箱请等等」
- [ ] 四个文件都能取到：`data.js` / `api.js` / `config.js` / `index.html`
- [ ] `?static=1` 正常（关动画）
- [ ] `?live=1` 角标显示「在线 · 真实池子」
- [ ] 手机打开链接，版面不塌、不横向滚动
- [ ] 四页在 1280×720 / 1440×900 / 1024×768 / 1920×1080 下均不溢出（见下方分辨率矩阵）
- [ ] 顶栏「今天第 N 份」与数据库实际条数一致
- [ ] 提交一次，序号 +1
- [ ] 断网后刷新，角标变「离线 · 演示数据」，演示照常
- [ ] 仓库有 `demo-ok-1` tag
- [ ] 伙伴的 collaborator 邀请已接受

**一行命令批量查资源：**

```bash
for f in "" data.js api.js config.js; do
  printf "%-12s " "${f:-index}"
  curl -s -o /dev/null -w "%{http_code}\n" "https://<owner>.github.io/<repo>/$f"
done
```

## 六点半、换到一个新仓库（比如用伙伴的）

### 什么不用改

| 项 | 要不要动 | 为什么 |
|---|---|---|
| `index.html` / `data.js` / `api.js` | **不用** | 全是相对路径，跟仓库地址无关 |
| `config.js` | **不用** | Supabase 地址是绝对的，且 CORS 是 `*`，任何域名都能连 |
| Supabase 里的东西 | **不用** | 数据库和前端托管是两回事 |
| 打过的 tag | 要重推一次 | `git push` 不会自动推 tag |

### 什么必须改

| 项 | 怎么改 |
|---|---|
| 本地 remote | `git remote set-url origin <新地址>` |
| 文档里的地址 | 全仓库有 **11 处**写死了旧地址，见下方命令 |
| Pages | 新仓库要重新开一次 |
| 之前发出去的链接 | **会失效**（除非用「转移」而不是「新建」） |

一次找出所有要改的地方：

```bash
grep -rn "旧账号\|旧仓库名" --include="*.md" --include="*.js" --include="*.html" .
```

### 三种做法，选一种

| 做法 | 旧链接 | 需要对方做什么 | 适合 |
|---|---|---|---|
| **A. 转移仓库**（推荐） | ✅ 301 跳转，不断 | 在邮件里点接受 | 想保住旧链接和 star |
| **B. 新建空仓库再推** | ❌ 直接失效 | 给你 push 权限 | 想彻底换到对方名下重来 |
| C. Fork | ❌ | 无 | 不适用，fork 不能改原仓库 |

### 做法 A：转移

```bash
gh api -X POST repos/旧账号/旧仓库名/transfer \
  -f new_owner=伙伴账号
```

对方会收到一封邮件，**必须点接受**才生效。
转移后 Pages 地址自动变成 `伙伴账号.github.io/旧仓库名/`，旧地址 301 跳转。

### 做法 B：新建再推

**伙伴先建一个空的 public 仓库**（免费版 Pages 不支持私有仓），然后：

```bash
# 1. 把这个环境加进协作者
gh api -X PUT repos/伙伴账号/新仓库名/collaborators/niuyongtaigr-oss -f permission=push
# 对方点接受后

# 2. 换 remote
git remote set-url origin git@github.com:伙伴账号/新仓库名.git

# 3. 推代码和 tag
git push -u origin main
git push origin --tags          # ← tag 不会自动跟着推，必须单独推

# 4. 重新开 Pages
gh api -X POST repos/伙伴账号/新仓库名/pages --input - <<'JSON'
{"source":{"branch":"main","path":"/"}}
JSON

# 5. 改文档里的 11 处地址
```

### 换完必查的五条

- [ ] `git remote -v` 指向新仓库
- [ ] `git ls-remote --tags origin` 能看到 `demo-ok-1`
- [ ] `https://新账号.github.io/新仓库/` 返回 200
- [ ] `?live=1` 角标仍是「在线 · 真实池子」（说明 config 没被弄坏）
- [ ] 手机打开新地址，版面不塌

### 五个坑

**① 新仓库必须是 public**

免费版 Pages 不支持私有仓库。建的时候就要选公开，事后改私有 Pages 会停。

**② tag 不会自动推**

`git push` 只推分支。回滚点靠 tag，漏推就等于没打：

```bash
git push origin --tags
```

**③ 如果对方仓库已有提交，push 会被拒**

```bash
# 先看差异
git fetch origin
git log --oneline origin/main..main

# 确实要覆盖对方的历史，才用
git push --force origin main
```

用 `--force` 前先想清楚：**对方仓库里有没有你不想丢的东西。**

**④ 提交作者不会跟着换**

历史提交的作者仍是原来的账号（`niuyongtaigr-oss`），仓库所有者变成对方而已。
想改作者要 `git rebase` 重写历史，代价大，**不建议为演示去做**。

**⑤ 文档地址漏改**

`grep` 出来的 11 处如果漏改，评委点 README 里的链接会 404。
改完再 grep 一遍确认清零。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| Pages 一直 404 | 还在构建，或 Source 分支填错 | 等 60 秒；检查 Settings → Pages |
| 页面白屏 | 少了 `data.js` | 页面会直接提示缺哪个文件 |
| `?live=1` 一直离线 | `config.js` 没上传或 key 错 | 检查 `config.js` 里两个值 |
| 改了代码线上没变 | Pages 构建有延迟 | 等 30–60 秒，或看 Actions 记录 |
| 手机横向溢出 | 忘了 `viewport` meta | 检查 `<meta name="viewport">` |

## 七点半、分辨率矩阵

页面按**视口高度**自动分档，不需要手动切：

| 视口高度 | 生效档位 | 效果 |
|---|---|---|
| > 860px | 完整版 | 1080p 投影、大屏 |
| ≤ 860px | 中度压缩 | 1440×900 笔记本 |
| ≤ 700px | 紧凑 | 1280×720 窗口化 |
| ≤ 640px 宽 | 单栏 | 手机 |

**实测（四页全部不溢出）：**

| 分辨率 | 视口 | apply | review | verdict | swap |
|---|---|---|---|---|---|
| 1280×720 | 633 | 600 | 468 | 627 | 345 |
| 1024×768 | 681 | 600 | 465 | 627 | 338 |
| 1440×900 | 813 | 612 | 488 | 666 | 362 |
| 1920×1080 | 993 | 796 | 641 | 841 | 517 |

> 注意：headless Chrome 的 `--window-size` 含窗口边框，实际视口会少约 87px。
> 量的时候要按视口算，不能按窗口高算——这一点踩过一次坑。
