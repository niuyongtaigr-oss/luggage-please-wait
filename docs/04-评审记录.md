# 《行李箱请等等》需求评审 + 设计与开发说明

> 评审对象：`行李箱请等等文案设计-2026年10月22日-来自【得到大脑】.pdf`（4 页，含四页文案、3 分钟逐字稿、应急话术）
> 评审视角：产品 / 设计 / 开发
> 交付物：`index.html`（四页可运行原型，单文件、零依赖、断网可跑）

---

## 0. 先说结论

**这份稿子最值钱的东西只有一个，而且它已经写对了：**

> 申请单上有一格，不是"你想去哪"，是"你其实不想面对什么"。

这一格是这个产品存在的原因。市面上所有"离开"类产品都在问"你要去哪"，只有它问"你在躲什么"。**整份稿子后面的所有设计，都应该为这一格让路。**

**但稿子目前有一个致命的结构问题：** 它是"文案稿"，不是"产品稿"。四页的**字**都很好，四页之间的**因果**是断的。断在三个地方：

1. 判决书到底是谁的？——演示流程在时间上不成立
2. 两个池子被当成一个池子——循环是断的
3. 页面四的标题预设了"走不成"——但投票可能投出"去吧"

以及一个战略问题：

4. **产品里没有任何 AI**，但这是一个 AI hackathon。

下面逐条说，每条都给可执行的改法。

---

## 1. 五个必须先解决的硬问题

### 1.1 判决书是谁的？——全稿最大的叙事漏洞

把演示流程按时间排一遍：

```
0:00  我填表（离开：这个酒店 / 不想面对：明天下午的路演）
       ↓ 提交
1:00  我是审批人，审别人
       ↓ 投票
1:40  判决书：41 个人看了，27 个人说再想想
```

**问题：** 判决书上的两行字是"你想离开的：这个城市 / 你真正想躲的：下个月的转正答辩"——这是**我自己填的**，所以它是我的判决书。但我 30 秒前才交上去，哪来的 41 个人？

评委只要问一句"这 41 个人是什么时候看的"，整段演示就崩了。这不是小瑕疵，这是流程在物理上不成立。

**改法（原型已实现）：** 把判决书明确写成**上一轮**的结果，并在页面二把"以审换审"的规则说清楚：

> 你交的第 47 份还在转盘上。先帮一个人看一份——这是你的票。
> （判决书页）你的牌，转回来了。

这样时间线自洽：我交的是今天这一轮，我审的是别人的，我看到的是**我昨天那一轮**的结果。演示时口头补一句"这是昨晚跑通的那一轮"就够了。

**顺带解决冷启动：** "必须先审一份，才能看到自己的判决书"——这一条规则同时回答了三个问题：审批人从哪来、用户为什么要写理由、池子怎么转起来。稿子说"池子就这么循环起来的"，但没给动力；这条规则就是动力。

---

### 1.2 产品里没有任何 AI

稿子最自豪的一句是：

> 审批理由必须由人填，不让模型代写，因为陌生人写的那句话才是这个产品唯一不可替代的东西。

**这句话在产品上完全正确**，我一个字都不想改。但它同时说明：模型在这个产品里没有位置。

而 2:20–2:50 那段"讲机制拿技术分"，讲的是 Kiro 的 Spec 流程（requirements → design → tasks）。**流程不是技术。** 评委听到的会是："我们用 AI 写代码，但产品里没有 AI。"

**改法：让模型不做作者，做护栏和调度。** 三个落点都不违反"不让模型代写"：

| 落点 | 做什么 | 为什么不算"代写" |
|---|---|---|
| **伤人预警** | 理由命中羞辱/说教模式时，不拦截，只提示"这句话可能有点重"，发送权仍在人手里 | 它不生产任何一个字，只在你准备伤人的时候碰你一下 |
| **理由聚类** | 41 条理由不按点赞排，按态度聚成 3 类（劝走 / 劝留 / 给小路），每类取一句 | 排序和归类，不生成 |
| **沉默路由** | 24 小时没人说话的申请，模型只负责把它重新推上传送带 | 只做调度，不产出内容 |

第一条可以直接变成一句路演金句：

> 这个产品里，AI 不写字。AI 只在你准备伤人的时候，轻轻碰一下你的手。

这句话同时解决了"AI 含量"和"你们是不是在用 AI 劝人别走"两个质疑。

**注意：** 稿子里 "最高赞那句" 的机制有伦理风险——点赞天然奖励最刻薄的话，评委一定会问"凭什么让陌生人决定别人的人生"。用"聚类 + 三类各一句"替代"单一最高赞"，是最省事的解法。

---

### 1.3 两个池子被当成一个

页面四的结尾：

> 点"我也交一条"跳回页面一，池子就这么循环起来的。

**但页面一是"交申请"（你要离开哪），页面四是"交小路"（咖啡馆在二楼）。** 这是两种完全不同的东西。用户想贡献一条"别急着签，先去小区楼下坐一个下午"，结果被要求填"我要离开哪"——投稿动机当场断掉。

稿子里的"循环"是设计者的一厢情愿，不是用户路径。

**改法（原型已实现）：** 拆成两个池子，小路单独三格：

> 你在哪 / 待了多久 / 一条能用的事

三格填完，卡片立刻进池子，提示"池子里多了一条"。这才是真的循环。而且"待了多久"这一格（九年、六年、搬过四次）比任何形容词都有说服力。

---

### 1.4 页面四的标题预设了结果

> 标题：走不成，可以先换一条

这句话默认了多数人投"再想想"。但如果这一轮 27 票里"去吧"过半，页面四的标题、副标、整页情绪全部不成立。

**改法：** 标题随票型分支。

- 多数"再想想" → **走不成，可以先换一条**
- 多数"去吧" → **那就走。走之前，先装一条进去**

两套文案共用同一张卡片池，成本几乎为零。原型里已经按票型写了分支函数。

---

### 1.5 命名系统在跟产品立场打架

> 我们不是在劝你别走。

这是收尾的立场。但整份稿子的命名是：

| 页面 | 稿子里的名字 | 给人的感觉 |
|---|---|---|
| 二 | 审批页 | 你在被审 |
| 三 | 判决书 | 你被判了 |
| 二 | 驳回时的追加格 | 你被驳回了 |
| — | 去吧 / 再想想 | 二选一的裁决 |

**产品在说"我们不决定"，文案在说"我们判决"。** 评委问"凭什么让陌生人决定"，稿子的回答是"不决定，只说话"——但读者从头到尾读到的都是"决定"。

**改法（不推翻，只加一句）：** "判决书"这个词有记忆点，别扔。在它下面加一行自嘲式免责：

> 这只是 41 个人说的话，不是判决。走不走，最后一下还是你自己的手。

这一行同时做三件事：化解伦理质疑、保留戏剧性、把决定权还给当事人。原型已加。

## 2. 文案层的自相矛盾（可直接改，逐条对照）

| # | 稿子原话 | 问题 | 建议改成 |
|---|---|---|---|
| 1 | "表单四格" | 下面表里列了 **5 行**（场景 + 4 个文本格）。读者会数错，"第四格是关键"就对不上号 | 写"场景一格 + 正文四格"，并明确"第四格 = 我其实不想面对什么" |
| 2 | "第四格是整个页面的关键" vs 表里"我其实不想面对什么 / **否**" | **灵魂字段是选填**。这是全稿最该改的一处 | 改成必填，但给一个"我说不清"的按钮作为合法答案——既守住灵魂，又不逼人 |
| 3 | "场景：旅行 / 求学 / 出差 / 租房（四选一）" vs 逐字稿"旅行、开学、出差、搬家" | 两套词；而且**"离开一段关系 / 离开一份工作"装不进去**——而这恰恰是最有共鸣的离开 | 加一格"说不清"；或把场景改成"旅行/求学/出差/租房/说不清" |
| 4 | "你的申请已放入今天 47 份里" vs "今天第 12 份" | 逻辑上能对上（47 里抽第 12），但读者会卡一下 | 统一成"你是今天的第 47 位 / 现在轮到你审第 12 位" |
| 5 | 空池文案"这个池子今天刚开，**已有 3 条**在等第一个人" | "空池"却有 3 条，自相矛盾 | "这个池子今天刚开。你是第一个。" |
| 6 | 应急话术："钱包拦的是几十块，行李箱拦的是几天假、一个月房租" | 这是**量级**差别，不是**性质**差别。评委心里会想"所以还是同一类东西，只是贵一点" | 换成性质差别：**钱包拦的是一次冲动，冲动会过去；行李箱拦的是一次逃跑，逃跑不会。**（这句就该是开场第一句） |

## 3. 开场 15 秒打错了靶

稿子说：

> 你必须在开场就把"买箱子"这个误解拆掉，否则后面八句话都在给评委纠错。

**但评委听到"行李箱请等等"，第一反应不是"这是个卖箱子的"，而是"这是钱包请等等换了个皮"。** 前者几乎不会发生，后者一定会发生——它在稿子里只出现在"应急话术"的第四行，太晚了。

而且稿子自己把最强的一句放错了位置：

> 钱包请等等，拦的是你的手。手缩回来，事就过去了。
> 行李箱不一样。一个人拎起箱子，说明他要离开现在这个地方。

**这句"手 vs 走"的对比，是整份稿子最有杀伤力的一句，现在是 0:15 才出现。** 它应该在第一句。

**建议的开场：**

> 我们做的东西叫「行李箱请等等」。
> 先说清一件事：它不是钱包请等等。
> 钱包拦的是你的手，手缩回来，事就过去了。
> 行李箱拦的是你的走——一个人拎起箱子，说明他真的要离开现在这个地方。
> 而这个决定，没有人替他做过。

四句话，15 秒，同时拆掉两个误解，还立住了差异。

## 4. 其他产品缺口（按优先级）

1. **投票只有两个选项。** 真实生活需要第三个："等一下 / 换一条"。页面四其实就是第三选项，但它被放在投票**之后**。建议投票三选一：`去吧 / 再想想 / 给他一条更小的路`。
2. **身份是装饰。** 稿子说三种身份"语气完全不同"，但投票结果只统计去吧/再想想。身份应该真的改变产品：改变按钮的说法、改变理由框的提示语、改变理由在判决书里的落款。（原型已实现）
3. **只有驳回才给小路。** "如果他先不走，你觉得他可以先去哪"这一格是全产品最有温度的接口，但它藏在驳回流程里——投"去吧"的人反而给不了建议。建议投票后**统一**给一个"给他一条更小的路"。
4. **没有护栏。** 被审的人没有任何反馈通道。建议：最高赞那句下面给两个小按钮「收下了 / 过了」（原型已做）。
5. **"被点赞最多"会系统性选出最刻薄的话。** 建议改成"14 个人觉得有用"——从"好笑"改成"有用"，直接改变激励。
6. **隐私颗粒度。** 四格组合起来是可识别的（"这个城市 + 租房 + 三年没交新朋友"）。页面必须有一句"不显示是谁写的"。
7. **没有"回来"的理由。** 判决书看完就结束了。建议保留一个"三天后回来看看"的钩子。
8. **数字全是编的。** 稿子自己在应急话术里承认"居住类的是我凭经验写的，还没验证"——**这句话在台上说出来是减分的**。更好的做法是把来源标在卡片上（`来源：公开史料` / `来源：居住经验 · 未核实`），让诚实变成设计的一部分，而不是被问出来的坦白。

## 5. 设计说明

### 5.1 视觉概念：行李牌

四页不是四个网页，是**四张不同状态的行李牌**：

| 页 | 物件状态 | 视觉处理 |
|---|---|---|
| 一 交申请 | 一张**待填**的空白牌 | 米白纸、打孔、切角、微微倾斜 |
| 二 审批 | 一张**别人的、旧一点**的牌 | 同一个形状，纸色更旧、反向倾斜 |
| 三 判决 | 一张**撕下来的提取凭证** | 虚线撕口、两侧半圆缺口、条码位 |
| 四 换一条 | 一张**能翻面的实物卡** | 3D 翻转，背面整块荧光黄 |

这个隐喻统一了四页，而且它同时解释了产品：**你的申请就是一只箱子，被放上传送带，陌生人从转盘上取下来看。**

### 5.2 色彩：只有三个颜色

- 墨黑 `#0A0A0B` —— 底
- 米白 `#F2EDE2` —— 纸
- 荧光黄 `#D9FF43` —— **唯一高亮**，只给"该动手的地方"和"关键那一格"
- 朱红 `#FF3B1F` —— **唯一警示**，只给"再想想"

约束越狠，越抓眼球。整份稿子里唯一被荧光黄铺满的地方，就是「我其实不想面对什么」——**用颜色告诉用户这一格最重要**，比任何文案都有效。

### 5.3 字体与版面

- 中文用 900 字重 + `letter-spacing: -0.05em`，做压迫感。
- 所有编号、时间、计数用等宽体（`GATE 01 / 04`、`TAG · 0047`、`47`、`41`），做出机场显示屏的味道。
- **1000px 以上切左右两栏**：左边编辑文字（标题 / 数字 / 说明），右边物件（牌 / 卡）。这样 16:9 投影**一屏能看完，不用滚动**——路演时这一条比什么都重要。
- **手机单栏，顺序重排**：先看到牌，再看到数字，最后看到别人说的话。

### 5.4 三个关键动效

1. **提交**：箱子滑上传送带，数字从 0 跳到 47，配文"你的申请已放入今天 47 份里"。
2. **投票**：一枚印章砸下来（"去吧"绿 / "再想想"红），下面跟着你刚写的那句话和身份。这是全场最该有掌声的 1.5 秒。
3. **翻卡**：3D 翻面，正面是别人的经验，背面是"9 个人验证过 / 5 个人说值得"。

## 6. 开发说明

### 6.1 技术选择

| 决定 | 理由 |
|---|---|
| **单文件 HTML** | 现场最怕 CDN 挂、网断、构建失败。双击就能开，拷到 U 盘也能跑 |
| **零依赖** | 没有 React、没有字体请求、没有图片文件。全部 CSS 绘制 + 内联 SVG |
| **hash 路由** | `#apply / #review / #verdict / #swap`，刷新不丢页，排练时可以直接跳页 |
| **`?static=1`** | 关闭全部动画，用于截图、打印、做 PPT |
| **`⌘/Ctrl + K`** | 一键填入演示数据。**现场千万别用输入法打中文**——会慢、会错、会尴尬 |

### 6.2 状态机

```
apply ──提交──> review ──投票+理由──> verdict ──按钮──> swap
                                                  └─"我也交一条"─> 小路面板
```

严格渐进披露：选身份 → 才解锁投票 → 投完 → 才出现理由框 → 写完 → 提交按钮才变绿。每步只做一件事，演示节奏自然分段。

### 6.3 匹配规则（写死，可预测）

```js
同场景优先 → 全池兜底 → 随机取一
// ?static=1 时固定取第一条，方便排练出一样的结果
```

**关于原稿的"同地点优先"：建议删掉。** 理由有两条：
1. 隐私——"这个城市 + 租房 + 三年没交新朋友"本来就快被认出来了，再按地点匹配等于把同城的人凑到一起；
2. 价值——同地点 = 同温层，给不出"过来人"的视角。**同场景 + 跨人生阶段**才是真正有用的匹配。

### 6.4 已经埋好的健壮性

- 计数动画有 `setTimeout` 兜底：切到后台再切回来，数字不会停在 0。
- `prefers-reduced-motion` 全量适配。
- 全部交互有键盘路径和焦点态。
- 空值校验会抖动 + 定位到第一个没填的格子。
- 页面四标题按票型分支（代码已就位，当前演示池走"再想想"分支）。

### 6.5 如果要真做，后端最小实现

```
applications (id, scene, leaving, if_not, avoid, created_at, expires_at)
reasons      (id, application_id, identity, vote, body, likes, created_at)
cards        (id, where, how_long, thing, verified, worth, source)
```

- 队列：`expires_at > now` 且未被当前用户审过，`scene` 相同优先。
- 24h 过期：稿子的"今天的池子"是个好概念，但需要真的过期，否则池子越积越大、匹配质量下降。
- 不需要 WebSocket，5 秒轮询足够。

## 8. 如果只改三件事

1. **把"钱包拦的是手，行李箱拦的是走"提到第一句**（0 秒，不是 15 秒）。
2. **把"我其实不想面对什么"改成必填**，并给一个"我说不清"的出口。
3. **给判决书加一句"这不是判决"**，并把"最高赞一句"改成"三类声音各一句"。

这三条不改代码，只改文案和规则，一个下午能做完，但会把稿子从"文案很好"变成"产品站得住"。
