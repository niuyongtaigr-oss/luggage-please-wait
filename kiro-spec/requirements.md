# Requirements · 行李箱请等等

> Spec-driven development · 需求阶段
> 版本 1.0 · 2026-10-22
> 每条用户故事附带 EARS 验收标准（Ubiquitous / Event-driven / State-driven / Unwanted behaviour / Optional feature）

---

## 0. 产品定义

**把「我要走」这个念头，交给陌生人审一遍。如果被劝退，还你一条今天能走的路。**

核心洞察：申请单上有一格，问的不是「你想去哪」，是「你其实不想面对什么」。大部分人写不出为什么想走，但都写得出不想回哪。

---

## 1. 角色

| 角色 | 描述 |
|---|---|
| **申请人** | 想离开某个地方/状态的人，填表交出两行字 |
| **陌生人（审批人）** | 池子里的另一个匿名用户，选一个身份，写一句话 |
| **系统** | 只负责排队、去重、聚合，**不做判断、不写字** |

---

## US-01 交申请

**作为**一个想走的人，**我要**用四格说清我要离开哪、我不想面对什么，**以便**有人能读到。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-1.1 | Event-driven | **当**用户填完四个必填项并点击「交上去」**时**，系统**应**把申请写入今天的池子，并返回该申请在今天池中的序号 |
| AC-1.2 | Unwanted | **如果**任一必填项为空**，则**系统**应**不提交，标红该格，并把视图滚动到第一个空项 |
| AC-1.3 | Optional feature | **当**用户点击「我说不清」**时**，系统**应**向「我其实不想面对什么」填入一个合法答案，并允许提交 |
| AC-1.4 | State-driven | **当**「为什么想走」为空**时**，系统**应**仍然允许提交（该项为选填） |
| AC-1.5 | Ubiquitous | 系统**应**在提交后展示该申请在今日池中的序号，且该序号与池内实际条数一致 |
| AC-1.6 | Event-driven | **当**提交成功**时**，系统**应**播放上传动效（箱体滑过传送带 + 数字进位），并在 2 秒后进入审批页 |

## US-02 审批别人

**作为**一个刚交完申请的人，**我要**先读一份别人的申请并说一句话，**以便**我的票生效。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-2.1 | Event-driven | **当**用户进入审批页**时**，系统**应**从**今日池**中取出一份「不是自己交的、自己没审过的」申请 |
| AC-2.2 | Unwanted | **如果**取不出这样的申请（池子为空或只剩自己的），**则**系统**应**回落到演示数据，并在卡片下方显式标注「这一条是演示数据」 |
| AC-2.3 | State-driven | **当**用户尚未选择身份**时**，系统**应**禁用投票，并在点击投票时提示「先选一个身份」 |
| AC-2.4 | Event-driven | **当**用户选择一个身份**时**，系统**应**把该身份的语气同时应用到两个按钮的副标与理由输入框的占位提示 |
| AC-2.5 | State-driven | **当**用户投票后**时**，系统**应**才显示理由输入框（渐进披露，顺序为 身份 → 投票 → 理由 → 提交） |
| AC-2.6 | Unwanted | **如果**理由为空**，则**系统**应**禁用提交按钮，并显示当前缺失项 |
| AC-2.7 | Event-driven | **当**用户投票为「再想想」**时**，系统**应**额外显示选填格「如果他先不走，你觉得他可以先去哪？」 |
| AC-2.8 | Event-driven | **当**用户提交**时**，系统**应**播放盖章动效（落章 + 页面抖 2px），停留约 1.5 秒后进入判决书 |

## US-03 看判决

**作为**申请人，**我要**看到这一轮有多少人读了我、他们说了什么，**以便**我自己做决定。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-3.1 | State-driven | **当**展示判决书**时**，系统**应**显示两行：我想离开的、我真正想躲的 |
| AC-3.2 | Ubiquitous | 系统**应**显示「N 个人看了」与「M 个人说再想想」，其中 **N 为去重后的人数**（`count(distinct device_id)`），不是浏览量 |
| AC-3.3 | Ubiquitous | 系统**应**按**三类态度**各展示一句：劝走 / 劝留 / 给小路，各带身份落款 |
| AC-3.4 | Unwanted | **如果**还没有人读过这份申请**，则**系统**应**显示「你的牌还在转盘上，还没有人读到」，而不是显示 0 或占位假数 |
| AC-3.5 | Ubiquitous | 系统**应**始终显示免责句：这只是 N 个人说的话，不是判决。走不走，最后一下还是你自己的手 |
| AC-3.6 | Ubiquitous | 系统**应**在页脚印出这一轮的标识（如「上一轮 · 2026-10-22 23:40」），使时间线可解释 |
| AC-3.7 | Optional feature | **当**用户点击某句话下的「收下了 / 过了」**时**，系统**应**记录该反馈且不改变任何展示顺序 |

## US-04 换一条

**作为**被劝退的申请人，**我要**拿到一条今天就能做的事，**以便**这个决定不是只有「走 / 不走」两种。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-4.1 | State-driven | **当**多数票为「再想想」**时**，标题**应**为「走不成，可以先换一条」；**当**多数票为「走吧」**时**，标题**应**为「那就走。走之前，先装一条进去」 |
| AC-4.2 | Event-driven | **当**用户点击卡片**时**，系统**应** 3D 翻面，背面显示验证人数、值得人数与来源标注 |
| AC-4.3 | Event-driven | **当**用户点击「再抽一条」**时**，系统**应**切换到下一张路线卡，且同一轮内不重复 |
| AC-4.4 | Ubiquitous | 每张卡**应**标注来源（公开史料 / 居住经验·未核实） |

## US-05 伤人预警

**作为**产品的设计者，**我要**在审批人写的话可能伤人时轻轻提醒，**以便**保护被审的人，同时不替任何人写字。

**这是本产品唯一使用 AI 能力的地方。**

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-5.1 | Event-driven | **当**理由文本命中本地词库（羞辱 / 说教 / 嘲讽三类）**时**，系统**应**浮出提示「这句话可能有点重，要不要再读一遍？」 |
| AC-5.2 | Unwanted | **如果**命中词库**，则**系统**应**仍然允许发送，提交按钮不得被禁用 |
| AC-5.3 | Unwanted | **如果**用户修改掉触发词**，则**系统**应**自动收起提示 |
| AC-5.4 | Ubiquitous | 系统**应**在提示中标注「AI 护栏 · 本地词库 · 不拦截」，让能力边界暴露给用户 |
| AC-5.5 | Ubiquitous | 系统**应**在本地完成判定，不发送任何网络请求，断网可复现 |
| AC-5.6 | Unwanted | 系统**应不**对理由正文做任何改写、纠错、润色 |

## US-06 交小路

**作为**一个在这个城市待过的人，**我要**把我的一条具体经验交进池子，**以便**别人今天就能用上。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-6.1 | Event-driven | **当**用户填完三格（你在哪 / 待了多久 / 一条能用的事）并提交**时**，系统**应**把卡片立即放入池子 |
| AC-6.2 | Unwanted | **如果**任一格为空**，则**系统**应**不提交，并标红对应格 |
| AC-6.3 | Event-driven | **当**提交成功**时**，系统**应**立即把这张新卡设为当前卡，并提示「池子里多了一条」 |
| AC-6.4 | Ubiquitous | 系统**应**在卡面标注「来源：你刚交的 · 未核实」，不得伪装成已验证数据 |

---

## US-07 身份与去重

**作为**系统，**我要**在不要求登录的前提下，区分「不同的人」「同一个人」「不是自己」，**以便**「41 个人」这个数字是真的。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-7.1 | Ubiquitous | 系统**应**用伪匿名设备标识区分用户，不收集手机号、姓名、邮箱等任何 PII |
| AC-7.2 | Unwanted | **如果**同一设备对同一份申请再次提交理由**，则**系统**应**拒绝并把错误码 `already_reviewed` 返回给前端 |
| AC-7.3 | Unwanted | **如果**用户试图审批自己提交的申请**，则**系统**应**拒绝并返回 `self_review` |
| AC-7.4 | Ubiquitous | 「N 个人看了」中的 N **应**为去重后的设备数，不得为理由条数或页面浏览量 |
| AC-7.5 | State-driven | **当**用户返回查看自己的判决**时**，系统**应**通过设备标识匹配申请归属，无需登录 |
| AC-7.6 | Unwanted | 系统**应不**用 IP 地址做去重或计数（同一 WiFi 下所有人共用一个出口 IP） |

---

## US-08 降级与兜底

**作为**演示者，**我要**在后端不可用时仍然能完整演示，**以便**现场不会因为网络问题崩掉。

### 验收标准

| # | 类型 | 标准 |
|---|---|---|
| AC-8.1 | Unwanted | **如果**后端不可达或超时（1.5 秒）**，则**系统**应**自动回落到本地演示数据，且不阻断任何操作 |
| AC-8.2 | Ubiquitous | 系统**应**用角标明确当前数据来源：`在线 · 真实池子` / `离线 · 演示数据` / 不显示（静态轨） |
| AC-8.3 | Unwanted | **如果**`data.js` 未加载**，则**系统**应**显示可读的错误提示，而不是白屏 |
| AC-8.4 | Ubiquitous | 系统**应**在无网络时保持全部功能可用，运行时不发起任何外部请求（静态轨） |

---

## 9. 非功能需求

| 项 | 要求 |
|---|---|
| 首屏 | 本地文件双击即开，无构建步骤 |
| 分辨率 | 1000px 以上双栏一屏可见；1280×720 / 1920×1080 均需实测 |
| 移动端 | 单栏，不横向溢出 |
| 可预测 | 同一操作路径必须得到同一结果（演示锁死第 3 条申请） |
| 无障碍 | 键盘可走完全程；焦点可见；适配 `prefers-reduced-motion` |

## 10. 明确不做

- 登录、手机号、实名认证、人机验证
- 积分、等级、连击、排行榜、抽卡、音效
- 模型生成或改写任何用户文案
- 同地点匹配（隐私 + 同温层）
